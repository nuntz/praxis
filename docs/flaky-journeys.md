# Flaky journeys

A journey that fails only under load, a few runs in a hundred, as #85's did. Every journey shares one Deployment, so `bun run test:e2e:stress` is where they show. A new journey is looped (step 1) before the full suite runs it, as one racing its own repeats is a full run lost. A journey that fails once in CI is filed with the run id, the failing line and the error, as #87 is, before the job is rerun: a rerun that passes keeps no evidence.

1. **Loop it alone.** `bunx playwright test <file> -g "<title>" --project=desktop --repeat-each=128 --workers=16` takes about 25 seconds, and a race failing one run in twenty shows several times in each. Each failure keeps its own folder under `test-results/`.
2. **Hold the answer.** A step that races a read still out (an Escape, a click or a pick made before the screen has its answer) may pass every run of the loop, as #87's did 128 times out of 128. Hold that tool's answers with `holdAnswers()` from `e2e/fixtures.ts` until the step is taken, then release them: the step then loses the race on every run, in seconds, and the held journey becomes the regression once the fix is in, as the links journey's Escape did.
3. **Log what the journey read, from a throwaway spec.** A trace holds each call and the page, not what `boundingBox()` or `evaluate()` returned, so a value read off the page is seen only by logging it. Log too whether the element seen a moment before is still attached (`elementHandle()`, then `isConnected`): one that is not was replaced, and what replaced it is the lead. What the server did is in its own log: run with `DEBUG=pw:webserver` and grep for the journey's tag, and read what the server holds with `page.request` against the tool the screen reads.
4. **Count it on every load.** A race that fails on timing usually happens on every load, and only the journey's timing varies. Count the event from a `MutationObserver` set up in `page.addInitScript`, as the main-screen journey counts each column's mounts: the count is red on every run, in seconds, and becomes the regression journey once the fix is in.
